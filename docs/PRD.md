## 1. 产品定位

Codex Link 是一个手机优先的远程 Codex 控制台。用户在浏览器中登录中心服务端，选择一台已安装 Codex 的电脑，即可查看和继续该电脑上的 Codex 对话、发送消息、处理审批、上传图片或文件，并管理仅 P2P 的 TCP 端口映射。

产品不提供远程桌面、屏幕控制或键鼠自动化。Codex 的运行、工作目录、模型凭据和本机配置始终留在目标电脑；中心服务端负责账号、设备发现、网页、信令、持久化和必要时的业务中转。

## 2. 问题与目标

### 2.1 用户问题

- 用户离开电脑后无法及时查看或继续本机 Codex 任务。
- 传统远程桌面在移动网络下体验差，也会暴露完整桌面。
- 多台电脑和多个 Codex 对话缺少统一的设备、会话和令牌管理入口。
- 内网调试服务通常无法安全、按需地提供给外部访问。
- 网页和桌面端同时操作同一 Codex 对话时，可能产生写入占用冲突。

### 2.2 产品目标

1. 在浏览器中完成远程 Codex 的主要对话工作流，无需暴露目标电脑的 HTTP 服务端口。
2. 优先使用浏览器与本机 Agent 的 WebRTC DataChannel，降低中心服务端业务流量；直连不可用时，普通控制台业务可按策略回退。
3. 让用户能从移动端高效浏览项目、最近对话和长对话历史，避免一次加载大量会话或事件。
4. 支持用户自助管理设备、Token 和 P2P-only 端口映射；首个用户及管理员可维护系统用户。
5. 在网页离开、切换对话或退出时及时释放写入占用，避免阻塞桌面 Codex。

### 2.3 成功标准

- 用户可在 5 分钟内完成服务端部署、创建 Token、桌面客户端连接和网页选设备。
- 直连可用时，会话命令、事件和附件不经过普通 HTTP/SSE/WebSocket 业务中转。
- 对话切换或网页关闭后，桌面 Codex 可以继续写入原对话，不出现遗留的 active writer 占用。
- 端口映射打洞、目标设备或目标主机不可用时，外部连接会失败，不会悄悄降级为 Agent WebSocket/HTTP 转发。
- 管理员无法被全部删除，系统始终保留至少一个管理员。

## 3. 范围与非目标

### 3.1 本期范围

- 中心服务端、网页控制台、Windows 图形客户端和命令行客户端。
- 账号、网页登录会话、Token、设备、对话缓存、事件、附件元数据、数据库迁移。
- Codex 对话浏览、恢复、新建、消息、队列、目标、审批、取消、附件、模型与推理强度设置。
- WebRTC P2P、内置 STUN-only 服务、普通业务回退策略和 P2P-only 模式。
- 用户级 TCP 端口映射，目标可为 Agent 本机或 Agent 可访问的局域网主机。
- 管理员用户管理和常规系统运维入口。

### 3.2 非目标

- 不提供远程桌面、屏幕共享、键鼠控制或本机 shell 直接暴露。
- 不在服务端保存 Codex、CCS 或模型 API Key。
- 不提供 TURN 中继；P2P-only 模式下无法打洞的网络不保证可用。
- 不支持 UDP 端口映射、自动修改 Docker 端口发布或自动配置公网防火墙。
- 不承诺多个写入端同时编辑同一 Codex thread；同一时间只允许一个写入端占用。

## 4. 用户与权限

| 角色 | 主要能力 | 约束 |
| --- | --- | --- |
| 未登录访客 | 注册、登录、读取公开网页资源 | 其他 `/api/*` 接口必须返回 `401` |
| 普通用户 | 管理自己的 Token、设备、对话、附件和端口映射 | 只能访问归属自己的数据与设备 |
| 管理员 | 普通用户能力，以及系统用户管理 | 不能将系统置于无管理员状态 |
| 本机 Agent | 使用用户 Token 登记设备、维持 WebSocket、连接本机 Codex | 不对网络监听 HTTP API，不保存网页密码 |

首个注册用户必须自动成为管理员。管理员删除用户、取消管理员角色或迁移旧数据库时，系统必须保证至少存在一个管理员；若需兜底，提升最早注册的仍存在用户。

## 5. 核心概念

| 概念 | 定义 |
| --- | --- |
| 中心服务端 / Relay | 部署在公网或受控网络的 Go 服务，提供网页、认证、MySQL 持久化、Agent WebSocket、P2P 信令和端口监听。 |
| 本机 Agent | 运行在安装 Codex 的电脑上的 Go 客户端，主动连接 Relay，并调用本机 Codex app-server。 |
| 设备 | 一个使用 Token 登录的 Agent 实例；设备有在线状态、名称、最后活动时间和所属用户。 |
| 对话 / Thread | Codex app-server 中的会话。Relay 缓存元数据与事件，不替代 Codex 作为事实来源。 |
| P2P 直连 | 浏览器与 Agent 建立的 WebRTC DataChannel，用于控制台命令、事件和附件。 |
| 服务端中转 | 普通控制台业务在 P2P 不可用且未启用 P2P-only 时，通过 HTTP/SSE/Agent WebSocket 完成。 |
| P2P 端口映射 | Relay 监听公开 TCP 端口，并通过独立 WebRTC DataChannel 让 Agent 连接目标 `host:port` 的调试功能。 |

## 6. 产品架构与数据流

```text
浏览器
  |  网页、登录、普通 API、P2P 信令
Relay + MySQL
  |  Agent WebSocket（设备登记、回退控制、同步）
本机 Agent
  |  本机 app-server 协议
Codex

浏览器 <========== WebRTC DataChannel ==========> 本机 Agent
```

1. Agent 主动以 Token 建立到 Relay 的 WebSocket，不要求目标电脑开放入站 HTTP 端口。
2. 浏览器选择在线设备后，通过 Relay 交换 SDP 与 ICE candidate；Relay 仅参与信令。
3. P2P 建立后，优先在 DataChannel 上传输控制台命令、会话事件和附件分块。
4. P2P 不可用时，普通业务按照 `WEBRTC_P2P_ONLY` 策略回退或失败；网页登录、设备发现与信令始终由 Relay 提供。
5. 账号、Token、设备、会话、事件与附件元数据写入 MySQL；服务端中转附件的二进制写入 `data` 卷。P2P 附件直接写入 Agent 本地数据目录。

## 7. 功能需求

### 7.1 账号与会话

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| FR-AUTH-01 | 系统必须提供注册、登录、退出和修改密码。 | 开放注册时可创建账号；关闭注册后返回清晰错误；退出后 Cookie 失效。 |
| FR-AUTH-02 | 网页使用 HttpOnly 会话 Cookie，外部 API 与 Agent 使用 Bearer Token。 | 无有效认证访问受保护接口返回 `401`。 |
| FR-AUTH-03 | 用户可创建、复制、刷新和删除自己的 Token。 | 刷新后旧 Token 不能用于下次连接；删除后 Agent 下次重连失败。 |
| FR-AUTH-04 | Token 页面必须便于复制，复制失败时给出可操作提示。 | 鼠标与移动端均可完成复制或选中复制。 |

### 7.2 设备与桌面客户端

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| FR-AGENT-01 | Agent 支持图形界面填写服务端地址、Token 和设备名称，并启动后台 Agent。 | 正确配置后设备显示在线；连接错误在界面日志中可见。 |
| FR-AGENT-02 | 图形客户端关闭窗口时只隐藏到系统托盘。 | 托盘菜单提供恢复窗口和退出客户端；退出才停止 Agent。 |
| FR-AGENT-03 | Agent 需要预防重复启动。 | 同一数据目录的第二个后台 Agent 不会占用同一实例或创建重复连接。 |
| FR-AGENT-04 | 同一数据目录反复登录同一服务端时复用设备 ID。 | 网页不会因此产生重复在线设备；离线历史设备可由用户删除。 |
| FR-AGENT-05 | Agent 在网络故障后自动重连，并在每次启动或重连时校验 Token。 | 网络恢复后设备恢复在线；无效 Token 显示明确错误且不持续假在线。 |
| FR-AGENT-06 | 客户端无参数启动不得弹出命令行黑框。 | 双击打开图形窗口；后台进程使用 Windows GUI 子系统。 |

### 7.3 网页控制台与会话列表

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| FR-CONSOLE-01 | 登录后先展示当前用户设备，用户只能进入在线设备。 | 离线设备不能打开控制台，且显示在线状态和关联 Token 信息。 |
| FR-CONSOLE-02 | 控制台按项目与最近对话组织历史。 | 已选择项目时新对话加入该项目；未选择项目时加入最近对话。 |
| FR-CONSOLE-03 | 项目和最近对话初始只显示有限条目，支持按批次展开和拖放排序。 | 列表不一次渲染全部历史；顺序在刷新后保持。 |
| FR-CONSOLE-04 | 长对话历史必须向上滚动时按需加载。 | 首次恢复不拉取完整历史；继续向上滚动时追加更早事件且不跳动阅读位置。 |
| FR-CONSOLE-05 | 控制台标题、设备状态和当前会话状态必须稳定可见。 | 页面滚动时标题栏不随消息内容消失；窄屏文字不超出容器。 |
| FR-CONSOLE-06 | 支持浅色与黑色主题。 | 用户切换后界面立即生效并保存偏好。 |

### 7.4 对话、消息与 Codex 工作流

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| FR-CHAT-01 | 用户可新建、恢复、归档对话，并查看流式回复、工具输出和错误。 | 操作结果同步到 Codex；断线后可从事件 ID 补齐最近事件。 |
| FR-CHAT-02 | 输入框必须支持多行、Enter 发送、Shift+Enter 换行、图片拖放和剪贴板粘贴。 | 附件在发送前可见，单文件最大 16 MB。 |
| FR-CHAT-03 | 用户可选择模型与推理强度。 | 设置应用于新会话和后续消息，并在当前会话区域可识别。 |
| FR-CHAT-04 | 页面显示上下文使用量。 | 收到 Codex 上下文事件后显示已用 token 与模型窗口大小；未知时显示明确空状态。 |
| FR-CHAT-05 | 用户可管理消息队列。 | 可新增、编辑、删除、重排和提升队列项；运行中输入新内容时可加入队列或优先发送。 |
| FR-CHAT-06 | 用户可设置或清除会话目标，并使用计划模式。 | 目标状态会随事件同步；关闭后不再显示为活动目标。 |
| FR-CHAT-07 | 用户可处理 Codex 审批并中止当前 turn。 | 审批请求可批准或拒绝；运行时发送按钮和停止按钮按状态切换。 |
| FR-CHAT-08 | 当另一写入端已占用线程时，网页提供只读历史而非错误崩溃。 | 页面清晰标识只读状态并禁止写入操作。 |

### 7.5 对话写入占用释放

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| FR-LOCK-01 | 网页从一个可写对话切换到另一个对话前必须释放前一个对话。 | Agent 对旧线程调用 `thread/unsubscribe`，新线程可恢复。 |
| FR-LOCK-02 | 新建对话、删除当前对话、切换设备、返回设备列表和退出登录前必须释放当前对话。 | 桌面 Codex 可继续操作已离开的对话。 |
| FR-LOCK-03 | 页面刷新、关闭或进入页面缓存时必须尽力释放。 | 通过 P2P 通知和带 Cookie 的 keepalive HTTP 请求触发幂等 release。 |
| FR-LOCK-04 | 正在运行的对话先被中止再释放。 | 不遗留持续写入的 turn；重复 release 安全成功。 |

### 7.6 P2P、STUN 与普通业务回退

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| FR-P2P-01 | Relay 提供 P2P 信令和 STUN-only UDP Binding 响应。 | 浏览器和 Agent 获得相同 ICE server 配置；STUN 端口不承载 TURN 或 DataChannel 中转。 |
| FR-P2P-02 | P2P 建立成功时，控制台命令、事件和附件优先走 DataChannel。 | 页面显示直连状态；Relay 普通业务接口不成为该链路的数据通道。 |
| FR-P2P-03 | `WEBRTC_P2P_ONLY=false` 时，P2P 失败自动回退 HTTP/SSE/Agent WebSocket。 | 用户仍可使用控制台，并能看到服务端中转状态。 |
| FR-P2P-04 | `WEBRTC_P2P_ONLY=true` 时，普通业务不得静默回退。 | P2P 断开后请求明确失败或事件不再转发。 |
| FR-P2P-05 | TCP 与 UDP 可共用相同数字端口，但必须分别在 Compose 中声明。 | 默认宿主机 `18787/tcp` 与 `18787/udp` 分别映射到容器 `8787`。 |

### 7.7 P2P-only TCP 端口映射

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| FR-PORT-01 | 每个登录用户可管理属于自己设备的 TCP 映射，无需管理员权限。 | 用户无法读取或修改其他用户的映射。 |
| FR-PORT-02 | 表单字段需明确并提供可点击问号说明。 | 映射名称、目标设备、目标主机地址、目标端口、公开端口与监听开关均有说明。 |
| FR-PORT-03 | 目标主机支持 Agent 本机和 Agent 能访问的局域网服务。 | `127.0.0.1`、局域网 IP、DNS/局域网主机名均可作为 `targetHost`；Agent 连接 `targetHost:targetPort`。 |
| FR-PORT-04 | 公开端口必须是有效 TCP 端口，且不能等于 Relay HTTP 端口。 | 冲突、无效或未发布端口返回清晰错误。 |
| FR-PORT-05 | 创建映射不会自动修改 Compose 或防火墙。 | 页面和文档提示用户手动发布 `listenPort:listenPort/tcp` 并放行防火墙。 |
| FR-PORT-06 | 该功能只允许 P2P DataChannel 链路，不使用 Agent WebSocket 或 HTTP 业务回退。 | 打洞失败、设备离线、目标主机不可达或 DataChannel 中断时关闭外部 TCP 连接。 |
| FR-PORT-07 | 页面显示监听、P2P 连接和最近错误状态。 | 用户可启用、停用、编辑、删除映射并看到故障原因。 |

### 7.8 系统管理

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| FR-ADMIN-01 | 管理员入口从右上角用户菜单进入。 | 系统管理与普通控制台分离，提供返回控制台动作。 |
| FR-ADMIN-02 | 管理员可查看用户、设置其他用户的管理员角色、删除其他用户。 | 当前用户不能在该页修改自己；删除会清理该用户受管数据。 |
| FR-ADMIN-03 | 系统必须保留至少一名管理员。 | 删除或降级最后管理员被拒绝或自动按规则补充管理员。 |

### 7.9 数据、迁移与可观测性

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| FR-DATA-01 | 空 MySQL 数据库启动时自动建表。 | 服务启动后 `schema_migrations` 与业务表存在。 |
| FR-DATA-02 | 版本升级自动执行新增迁移，且已执行迁移不可被静默修改。 | 迁移版本与校验记录持久化；修改既有迁移会拒绝启动。 |
| FR-DATA-03 | Relay 重启后账号、Token、设备、会话和事件数据保留。 | MySQL volume 不被容器重建删除。 |
| FR-DATA-04 | 客户端图形界面展示后台日志。 | 用户能看到连接、重连、登录和异常退出诊断。 |
| FR-DATA-05 | 健康接口返回服务、数据库、迁移和当前用户设备状态。 | 认证后 `/api/health` 可用于发布后核验。 |

## 8. 关键用户流程

### 8.1 首次部署与连接

1. 运维人员创建 `.env`，配置 MySQL 密码，执行 `docker compose up -d --pull always`。
2. 用户打开网页，注册首个账号并自动获得管理员角色。
3. 用户在网页创建客户端 Token。
4. 用户在安装 Codex 的 Windows 电脑打开图形客户端，填写服务端地址、Token 与设备名，点击连接并启动。
5. Agent 登记设备、校验 Token、建立 WebSocket 并同步可用对话。
6. 网页显示在线设备，用户选择设备进入控制台。

### 8.2 远程继续对话

1. 用户从项目或最近对话选择一个 thread。
2. 网页先释放旧线程，再恢复新线程；P2P 可用时通过 DataChannel 发起请求。
3. 页面加载最近事件，用户向上滚动时按需加载更早历史。
4. 用户发送消息、附件或队列项，并实时查看 Codex 输出、工具日志、上下文与审批请求。
5. 用户切换对话、返回设备、退出或关闭页面时释放当前写入占用。

### 8.3 创建局域网服务映射

1. 用户打开侧栏“P2P 端口映射”。
2. 选择能够访问目标网络的 Agent 设备。
3. 填写目标主机地址，例如 `192.168.1.20` 或 `nas.local`，以及该服务的 TCP 端口。
4. 填写服务端公开 TCP 端口；运维人员在 Compose 与防火墙中提前发布该端口。
5. 用户保存并启用映射，确认页面显示监听状态与 P2P 连接状态。
6. 外部请求进入公开端口后，Relay 与 Agent 建立独立 DataChannel；Agent 连接目标主机并开始字节复制。
7. 任一 P2P 条件失败即关闭该外部连接，不使用普通业务中转补偿。

## 9. 安全与隐私要求

1. 不得提交 `.env`、密码、完整 Token、Cookie、API Key、CCS Key 或本机运行缓存。
2. 网页 Cookie 必须为 HttpOnly；密码仅用于认证流程，Agent 不保存网页密码。
3. 用户数据、设备、会话、附件与端口映射必须按用户隔离。
4. Agent 仅主动出站连接 Relay，不开放本地 HTTP 控制端口。
5. 公网部署必须使用防火墙、受控访问网关或受控内网限制来源；端口映射是用户主动暴露的能力，页面必须说明风险与前置网络配置。
6. P2P 端口映射允许访问 Agent 所在网络可达的主机，因此只应授予可信账号，并明确记录映射名称、目标、创建者与状态。
7. 服务端日志不得输出完整 Token、密码或附件二进制内容。

## 10. 非功能要求

| 类别 | 要求 |
| --- | --- |
| 响应式体验 | 网页优先适配移动端，窄屏下侧栏、对话和输入框不得溢出或重叠。 |
| 性能 | 会话列表和历史事件使用分批/懒加载，避免长历史一次占满浏览器内存与网络带宽。 |
| 可用性 | Agent 断网后自动重连；Relay 与 MySQL 重启后数据可恢复。 |
| 可观测性 | 服务端提供健康信息；客户端提供滚动日志；端口映射提供监听与错误状态。 |
| 兼容性 | 服务端镜像可在 Docker Compose 部署；Windows 客户端由远程交叉编译产出，无需在目标电脑安装 Go/Node。 |
| 发布 | 每次提交自动递增三段式修订版本，并在远程构建服务器推送版本标签与 `latest`。 |

## 11. 发布验收清单

### 11.1 服务端

- [ ] `docker compose config -q` 通过。
- [ ] `docker compose up -d --pull always` 后 MySQL healthy、Relay running。
- [ ] 网页根路径返回 `200`，未认证受保护 API 返回 `401`。
- [ ] 空库可自动迁移，已有库可升级且 `/api/health` 返回正确 `schemaVersion`。
- [ ] 版本镜像与 `latest` 的 manifest digest 一致。

### 11.2 网页与客户端

- [ ] 网页注册、登录、改密、Token 创建/刷新/删除、设备显示与离线设备删除可用。
- [ ] 图形客户端可连接、隐藏至托盘、恢复、退出、展示日志，并阻止重复后台启动。
- [ ] 对话新建、恢复、归档、消息、附件、审批、取消、队列、目标、模型和推理强度可用。
- [ ] 对话切换、页面刷新、退出登录后，桌面端可继续写入原 thread。
- [ ] P2P 直连与 `WEBRTC_P2P_ONLY` 回退/拒绝策略符合配置。
- [ ] 局域网目标端口映射可创建，且 P2P 失败时不回退至普通 Relay 业务通道。

## 12. 后续演进方向

- 增加可配置的权限模型，例如端口映射审批、设备共享和只读协作。
- 为设备、端口映射和登录增加审计日志与通知。
- 在不破坏 P2P-only 语义的前提下，提供更细粒度的网络诊断与连通性自检。
- 评估官方 Codex app-server 稳定的多端 thread 附着能力，以改善只读降级与写入切换体验。
- 在明确安全边界和授权模型后，评估更多平台的图形客户端支持。
